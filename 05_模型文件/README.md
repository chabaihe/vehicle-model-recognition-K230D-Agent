### 关于 INT8 ONNX（含实测精度差异）

对浮点模型做了 **ONNX Runtime 动态量化**，并随仓库分发 INT8 版。
在 **193 张测试图（20 个类别）** 上的实测对比：

| 指标 | 浮点模型（FP32） | 动态量化（INT8） | 差异 |
|---|---:|---:|---|
| 体积 | 97.41 MB | **24.53 MB** | 缩至 25% ✅ |
| 该子集 Top-1 准确率 | 94.30% | **91.71%** | **−2.59 pp** ⚠️ |
| 两者预测一致率 | — | 96.37% | — |
| CPU 单张推理耗时 | 131.5 ms | **737.7 ms** | 慢 5.6× ❌ |

两条结论：

**其一，动态量化有精度损失，约 2.6 个百分点。**
早先用 40 张图抽样时一致率是 100%，样本放大到 193 张后实际是 96.37%。
所以"量化无损"这种说法在小样本下很容易得出错误结论。

**其二，动态量化在 CPU 上不提速，反而慢 5.6 倍。**
原因是动态量化只量化权重，卷积仍需在执行时把权重反量化回浮点，
反量化开销超过了低精度存储的收益。

**为什么仍然分发 INT8 版？**
它的价值是**体积小、开箱即用**，让 clone 下来的人 5 分钟内就能看到 Agent 跑起来。
它适合做功能演示，不适合作为精度基准。

> ✅ **精度基准以浮点模型为准**：测试集 Top-1 **86.77%**、Top-5 98.16%、大类 98.24%。
> 这是 1000 类全量测试集上浮点模型的结果，与 INT8 版无直接可比性。

**结论**：量化能否提速，取决于目标硬件**是否有整数运算的专用加速单元**。

- **K230D 的 KPU 有 INT8 硬件加速** → 用量化模型，28 FPS ✅
- **普通 CPU 没有** → 保留浮点模型 ✅

## 类别标签表

### class_names_cn.txt（板端使用）

1000 行，每行一个类别名，格式为「品牌_车型」：

```
江铃_凯运
远程汽车_远程星智H
东风风神_东风风神E70
宇通客车_宇通T7
曹操汽车_曹操60
宝马_宝马M5
捷豹_捷豹F-PACE
比亚迪_海豚
...
```

> ⚠️ **每一行的顺序必须与训练时的类别编号一致**。
> 这是很隐蔽的坑：顺序错了会导致推理正常但标签整体错位。

### class_names_full.csv（完整信息）

包含类别编号、中英文名称、车辆大类等信息：

| 列 | 说明 |
|---|---|
| `class_id` | 类别编号（0000–0999） |
| `name_cn` | 中文名称「品牌_车型」 |
| `big_type` | 车辆大类（SUV / 轿车 / 卡车 / MPV / 跑车 / 微面 / 轻客） |
| `n_train` / `n_val` / `n_test` | 各划分的样本数 |

**七大类分布**：

| 大类 | 类别数 |
|---|---:|
| SUV | 422 |
| 轿车 | 298 |
| 卡车 | 101 |
| MPV | 69 |
| 跑车 | 44 |

## 模型精度

| 指标 | 数值 |
|---|---:|
| 测试集 Top-1 | **86.77%** |
| 测试集 Top-5 | 98.16% |
| **车辆大类准确率** | **98.24%** |

**已知局限**：

- 训练图以正面和侧前方 45° 为主，**正侧面识别率会下降**
- 置信度不是校准概率，**不能直接用来判断对错**
- 同款车的不同动力形式（燃油/插混/纯电）容易混淆
