# 技术路线思考：云端大模型 vs 端侧小模型

> 来源：项目后期的实测与讨论
> 定位：回答"为什么端侧深度学习在今天依然有意义"
> 相关：[12_置信度观察与结论.md](<12_置信度观察与结论.md>)、[10_K230D上板实战指南.md](<10_K230D上板实战指南.md>)

---

## 一、核心论点

> **技术没有优劣之分，只有合适之分。**
>
> 深度学习是较早的技术范式，它有明确局限（**依赖特定数据集**）；
> 当前的多模态大模型靠**海量预训练 + 外部工具（API）**补足了知识边界，
> 但它**吃设备**——需要 GPU、需要大内存、需要联网。
>
> 而在 **128 MB 运行内存、没有独立 GPU、只有 KPU** 的 K230D 上
> 成功部署了深度学习模型，**离线实时 28 FPS**；
> **同一个板子，连最小的 LLM 都装不下。**

---

## 二、三条论据（全部有实测支撑）

### 论据 1：深度学习依赖特定数据集 —— 有实证

| 数据集 | Top-1 | 关键局限 | 后果 |
|---|---|---|---|
| Stanford Cars | **91.33%** | **中国品牌 0 个**；止步 2012 年 | **认不出中国道路上的车** |
| **Car-1000** | **86.77%** | 视角以正面/侧前方为主 | 正侧面不适用（已知边界） |

**91.33% 这个"高分"是无效的** —— 因为它的训练数据不覆盖目标场景。

> **结论**：**精度数字只有在数据分布匹配时才有意义。** 这是深度学习最本质的局限。

### 论据 2：LLM 靠"预训练 + 外部工具"补足知识边界

实测 Tavily 搜索中文车辆信息的效果：

| 查询 | 返回内容 |
|---|---|
| 小米SU7 参数配置价格 | ✅ 三款配置、续航（700/800/830km）、售价，来源含"汽车之家" |
| 宝马M5 2024款发动机 | ✅ V8 双涡轮 + 电机，717 马力，8AT |
| 比亚迪秦PLUS DM-i 续航 | ✅ 纯电 210km、综合 2110km、25.28kWh 电池 |

**机制**：LLM 的知识**冻结在训练时刻**，所以需要工具去**取回实时信息**。

```
用户提问 → LLM 思考（知道自己不知道价格）→ 调用搜索工具 → 拿到真实数据 → 生成回答
```

**这就是"外部 API 充当手足、变相对抗幻觉"的含义。**

### 论据 3：LLM 吃设备，无法端侧部署 —— 量级对比

| | **我们的 ResNet-50** | **云端 LLM** | 倍数 |
|---|---|---|---|
| 参数量 | **2,556 万** | 数百亿 ~ 上万亿 | **约 1,000×** |
| 运行时内存 | **25.87 MB** | 上百 GB | **约 4,000×** |
| 硬件要求 | **KPU（6 TOPS），无 GPU** | **GPU 集群** | — |
| 功耗 | **几瓦**（充电宝可用） | 千瓦级 | — |
| 成本 | **¥300 开发板** | 单卡上万 | — |
| **能否装在 K230D 上** | ✅ **能，28 FPS** | ❌ **不能** | — |

**这是最有力的一个数字对比。**

## 三、诚实的限定（让论证更严谨）

> **不是"所有 LLM 都上不了端侧"，而是"这个规模上不了"。**

| 类型 | 内存需求 | 端侧可行性 |
|---|---|---|
| 云端大模型（GPT-4 / DeepSeek 量级） | 上百 GB | ❌ 完全不可能 |
| 7B 级小模型 | 4 ~ 8 GB | ⚠️ 树莓派级可以，**K230D 不行** |
| **亚 100 MB 专用模型（我们的）** | **约 128 MB** | ✅ **可以** |

**加上这个限定，"合适"的判断标准就清楚了**：

> **不是比模型大小，而是看**内存预算、延迟要求、能否离线**这三个约束。**

## 四、两条路线并列（都是正确且好用的）

```
┌────────────────────────────────────────────┐
│  路线 A：电脑 + 云端 LLM（虚拟空间使用）      │
│    ├─ DeepSeek API：看图识别车辆        ← LLM 在云端
│    ├─ Tavily API：查车型参数/价格        ← 工具在云端
│    └─ 浏览器页面展示                          │
│    特点：精度高、能对话、知识新、需联网        │
└────────────────────────────────────────────┘
                    ↕（两条路线对照展示）
┌────────────────────────────────────────────┐
│  路线 B：K230D + 本地小模型（实物部署）      │
│    └─ ResNet-50 本地推理                 ← 模型在端侧
│    特点：离线、28 FPS、零成本、¥300          │
└────────────────────────────────────────────┘
```

| 维度 | 路线 A（云端 LLM） | 路线 B（端侧小模型） |
|---|---|---|
| 运行位置 | 电脑 + 云端 | **K230D 本地** |
| 是否需联网 | ✅ 必须 | ❌ **完全离线** |
| 实时性 | 秒级（含网络往返） | **28 FPS** |
| 识别精度 | 更高（通用大模型） | 1000 类，86.77% |
| 单次成本 | 有 token 费用 | **0** |
| 能解释/对话 | ✅ 能 | ❌ 只输出类别 |
| 适合场景 | 有网、要对话、要查资料 | **无网、要实时、要低成本** |

**结论：两者是分工，不是替代。**

## 五、结论摘要

> 同一个任务用两条技术路线各做了一遍。
>
> **一条是当下流行的方式**：电脑调用云端多模态大模型识别车辆，再通过搜索 API 补齐实时资料，最后生成回答。
> **另一条是更早的技术范式**：训练一个 25 MB 的专用模型，量化后塞进一块 **300 块钱、128 MB 内存、没有 GPU** 的开发板，**离线实时 28 FPS**。
>
> 做完之后的结论是：**技术没有优劣，只有合适。**
>
> 云端大模型的优势是**理解和表达**，代价是**必须联网、有延迟、有成本**；
> 端侧小模型的优势是**离线、实时、零成本**，代价是**精度受训练数据限制**。
>
> **深度学习确实有局限 —— 它的能力边界就是它的数据集。但正因为"小"，它能去大模型去不了的地方。**
>
> 能在 128 MB 内存、没有 GPU 的板子上跑通深度学习；
> 但同一块板子，连最小的 LLM 都装不下。**这不是 LLM 更高级，而是在 128 MB 这个约束下，LLM 这条路线走不通。**

---

## 六、这条主线的价值

| 层次 | 内容 |
|---|---|
| **技术层** | 完整的端侧部署链路（训练 → 量化 → 转换 → 上板） |
| **方法层** | 数据集决定能力边界的实证；量化对模型结构的敏感性 |
| **判断层** | **能根据约束选技术路线** —— 这比会调参更难 |
| **表达层** | 用实测数据讲清楚"合适"的标准 |

> **"能根据约束选对技术"，比"会用最先进的技术"更重要。**
> 这也是这个项目最想传达的一点。
