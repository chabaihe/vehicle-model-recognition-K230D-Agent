## 一、项目概述

本项目源于数字图像处理课程的大作业，任务是车辆型号识别，后续整理为可独立复现的完整工程。

**任务目标**：输入一张车辆图片，输出其具体车型。

项目分四个阶段完成：

| 阶段 | 内容 | 结果 |
|---|---|---|
| 一 | 用 Stanford Cars 建立基线模型 | Top-1 91.33% |
| 二 | 论证该数据集不适用，更换为 Car-1000 中国车型数据集 | Top-1 86.77%，车辆大类 98.24% |
| 三 | 模型量化并部署到 K230D 开发板 | 25.87 MB，板端 28 FPS，完全离线 |
| 四 | 搭建 ReAct 智能体，对照本地小模型与云端大模型 | 网页工具可独立分发 |

**一句话总结**：技术没有好用与不好用之分，只有合适与不合适之分。

## 六、关键决策与理由

这些是项目中做过的重要判断，记录在此避免重复讨论。

| # | 决策 | 理由 |
|---|---|---|
| 1 | 选择进阶任务（含训练 + 端侧部署） | 要求同时完成模型训练与真实硬件部署，贴合嵌入式方向 |
| 2 | 从 Stanford Cars 换到 Car-1000 | Stanford 止步 2012 年、中国品牌类别为 0，无法识别中国道路车辆 |
| 3 | 坚持用 ResNet-50 而非更小的 MobileNetV3 | 实测 MobileNetV3-Large 量化后精度掉落 17.33 个百分点，而 ResNet-50 仅掉 0.87 个百分点。端侧必须量化，所以更大的网络反而更划算 |
| 4 | 保留 Stanford Cars 成果不删 | 作为能力基线；两个阶段分别说明，体现数据集选择这一核心论点 |
| 5 | 不做两级分类 | 1000 类已达标，但保留分层评估结论作为工程兜底 |
| 6 | 撤下跨域测试结论 | 那批照片全是正侧面，角度过于极端，不代表正常表现 |
| 7 | 电脑端分发包保留浮点模型 | 动态量化虽把体积降到四分之一，但 CPU 推理反而慢了 5 倍；K230D 上有 KPU 的 INT8 加速所以用量化版 |

## 七、已踩过的坑

详细过程见 [`01_问题与发现汇总.md`](01_问题与发现汇总.md)。

| # | 坑 | 后果 | 规避方式 |
|---|---|---|---|
| 1 | 类别索引用错顺序 | 推理正常但标签整体错位 | 类别表必须以训练目录顺序为准并固化保存 |
| 2 | 类名含路径分隔符 | 类别数虚增 | 替换所有路径分隔符并唯一化 |
| 3 | 中文路径 | onnxruntime 量化时报 FileNotFoundError | 量化与推理走 ASCII 临时目录 |
| 4 | Python 输出缓冲 | 后台训练看不到进度 | 脚本加 `-u` 参数 |
| 5 | 数据加载 worker 冷启动 | 测速时严重低估吞吐 | 测速时跳过前若干批次 |
| 6 | nncase 不支持高版本 Python | 无法转换模型 | 单独建 Python 3.10–3.12 环境 |
| 7 | nncase 与 nncase-kpu 是两个包 | 提示找不到 k230 目标平台 | 两个都要装，注意文件名是下划线 |
| 8 | **归一化参数量纲配置错误** | 编译与运行都不报错，但识别结果全错、置信度恒为 100% | `input_range` 与 `mean`/`std` 必须用同一数值尺度 |
| 9 | 板卡默认从板载存储启动 | IDE 连不上，串口无输出 | 按住 KEY2 再复位，从 TF 卡启动 |
| 10 | 批处理文件用 UTF-8 编码 | Windows 中文代码页下乱码并报错 | 批处理文件只用 ASCII 字符 |

**其中第 8 条最隐蔽**：编译不报错、运行也不报错，只表现为结果异常。
定位方法是先在电脑端对拍排除模型问题，再在电脑上人为构造各种预处理错误逐一模拟，
发现只有"缺少归一化"会让置信度饱和，据此反推板端配置。

## 八、数据集

数据集**不包含在本项目内**（体积过大），需自行获取。

| 数据集 | 规模 | 用途 |
|---|---|---|
| Stanford Cars | 196 类 / 16,185 张 | 第一阶段基线 |
| Car-1000 | 1,000 类 / 166 品牌 / 140,267 张 | 第二阶段主数据集 |

Car-1000 的标签为中文「品牌_车型」格式，另附 7 类车辆大类标签，
年份覆盖 1960 年代至 2020 年代，数据源自中国汽车媒体「懂车帝」。

> 请通过数据集发布方提供的渠道获取，并遵守其许可协议，仅用于学习研究。

## 九、关于 API 密钥

`04_代码_网页Agent/` 中的云端识别与联网搜索需要 API 密钥。

项目内**不包含任何密钥**，只有 `config.example.ini` 模板。

`DEEPSEEK_API_KEY` 与 `TAVILY_API_KEY`。

> ⚠️ `config.ini` 已在 `.gitignore` 中，不会被提交到版本库。
