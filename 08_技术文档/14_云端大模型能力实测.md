# 云端多模态大模型能力实测

> 目的：为"云端 LLM vs 端侧小模型"的对比提供**实测数据**
> 相关：[13_技术路线思考.md](<13_技术路线思考.md>)
> 测试方法：向云端模型传入可控图像，比对返回文本与 `finish_reason`，并用 token 计数确认图像是否真正进入上下文

---

## 一、⚠️ 一次被更正的错误结论（记录教训）

### 错误结论

初期测试得出："**DeepSeek API 不支持图像输入**"。

### 依据（当时的现象）

| 测试 | 输入 | 结果 |
|---|---|---|
| 1 | 1×1 像素 PNG | flash 答"粉色" |
| 2 | 真实车辆图 ×2 | flash 返回空；`deepseek-v4-pro` 称"无法查看这张图片" |
| 3 | 纯红/蓝/绿 512×512 | **全部返回空** `content=''` |

### 为什么这个结论是错的

重新检查响应元数据后发现关键线索：

```
finish_reason = 'length'          ← 被截断，不是"不支持"
content = ''                      ← 空
reasoning_tokens = 200            ← 200 个 token 全花在"内部思考"上
max_tokens = 40                   ← 设置过小
```

**根因：`max_tokens` 设置过小。**

该模型**带思考链（reasoning）**。`max_tokens=40` 时，模型把全部预算用于内部推理，**还来不及输出正文就被截断**，于是 `content` 为空。

> **教训：`content=''` 不等于"不支持"。必须先看 `finish_reason` 与 `reasoning_tokens`。**

## 二、更正后的实测：视觉能力**完全可用**

### 测试设计

用**内容 100% 已知的纯色图**（真值无争议），`max_tokens=200`：

| 输入 | 模型回答 | 判定 |
|---|---|---|
| 纯红色 512×512 | `红色` | ✅ |
| 纯蓝色 512×512 | `蓝色` | ✅ |
| 纯绿色 512×512 | `绿色` | ✅ |
| 纯黄色 512×512 | `黄色` | ✅ |

**4 / 4 全对。**

### 图像确实被编码进去了（token 计数证据）

| 请求类型 | prompt_tokens |
|---|---|
| 纯文本（对照） | **41** |
| **文本 + 512×512 图像** | **225** |

**多出的 184 个 token 就是图像编码** —— 图像**被真实传递并参与计算**。

### 图像通道存在的直接证据

用外部 URL 方式时返回：

```
BadRequestError 400: .messages[0].image[0]:
  Failed to download image from https://...
```

**API 明确在处理 `image` 字段**，只是那个外链下载失败。

## 三、车辆识别精度实测（真值已知）

用 Car-1000 训练集图片（真值 = 类别标签），让模型识别品牌/车系/车型/大类：

| 图片 | **真值** | **DeepSeek 回答** | 判定 |
|---|---|---|---|
| `0005_0108.jpg` | 宝马_宝马M5 [轿车] | 宝马 / M5 / **F10 M5** / 轿车 / 把握高 | ✅ **全对（含底盘代号）** |
| `0006_0030.jpg` | 捷豹_捷豹F-PACE [SUV] | 捷豹 / F-PACE / SUV / 高 | ✅ 全对 |
| `0100_0464.jpg` | 金杯_金杯海狮王 [轻客] | 金杯 / 海狮王 / **轻客** / 高 | ✅ **全对（冷门轻客也对）** |
| `0500_0009.jpg` | 大众_T-ROC探歌 [SUV] | 大众 / 探歌 / **T-Roc** / SUV / 高 | ✅ **全对（中英文对应）** |
| `0000_0214.jpg` | 江铃_凯运 [卡车] | （空，`finish=length`） | ⚠️ 预算耗尽，**参数问题** |

**有效样本 4 张，全部识别正确。** 第 5 张仅因 `max_tokens` 设小导致输出为空，非能力问题。

### 观察结论

1. **多模态 LLM 在通用车辆识别上表现优秀** —— 品牌、车系、车身类型都能说对，甚至能给出底盘代号（F10）
2. **它同时"知道"通用常识** —— 例如能判断 F-PACE 是 SUV
3. **它不能给出精确的 1000 类分类** —— 输出是**自然语言描述**，不是固定类别的判别结果
4. **受 token 预算影响明显** —— reasoning 模型必须留足输出空间

## 四、⚠️ 重要更正：云端大模型**也会错**，而且错得更离谱

### 实测案例：曹操60（Car-1000 类别 0004）

用户在 Agent 界面实测了一张 **曹操60** 的照片（该图属于 Car-1000 测试集，真值确定）：

| 方法 | 识别结果 | 判定 |
|---|---|---|
| **本地 Car-1000 模型** | 曹操汽车_曹操60 **[轿车]** 置信度 **33.32%** | ✅ **完全正确** |
| **云端多模态大模型** | 哈弗枭龙MAX **[SUV]** 把握度高 | ❌ **错（类别错、大类也错）** |

**更关键的验证**：拿类别 0004 的 **8 张**图逐一测本地模型：

| 图片 | Top-1 |
|---|---|
| 0004_0001 ~ 0004_0008 | **全部 = 曹操汽车_曹操60** |

```
Top-1 命中: 8/8
Top-5 命中: 8/8
大类（轿车）正确: 8/8
```

### 云端为什么错？—— **它把模糊的车标"MAPLE"误读成了"HAVAL"**

用户核对原图后指出：**车头标志实际是 MAPLE（枫叶汽车），但云端模型误读成了 HAVAL（哈弗）。**

云端给出的"识别依据"（原话）：

> - 品牌标识：车头引擎盖前部有清晰的 **"HAVAL"** 字母标识，这是哈弗品牌的标志。
> - 前脸设计：车辆采用了纯电动车标志性的封闭式前脸……
> - 灯组造型：大灯是哈弗枭龙系列很有辨识度的 **"7"字形 LED 大灯**……
> - 新能源身份：车头悬挂的绿色车牌……

**看起来有理有据，但前提（品牌标识）就是错的** —— 后面整条推理链都建立在误读之上。

**更值得注意的是**：把同一张图发到 DeepSeek **网页版**，它先答"哈弗枭龙EV"，
被用户质疑后**当场承认**：

> "抱歉，我上一轮的回答有误，感谢你的指正。图片中的这辆车确实是曹操60。"
> —— 并改口列出正确依据：车头 **"MAPLE"** 标识、车牌位置 **"曹操60"** 字样、车尾 **"吉利"** 字标

### 这条更正推翻了先前的结论

先前用**单张宝马 M5** 测试时，云端答对、本地置信度只有 8.37%，于是得出"云端精度更高"。
**这个结论下得太早** —— 样本只有 1 张。

现在有了第二个案例，结论变成：

> **两者各有胜负，不能凭单张图判断谁更准。**
> 而且要评估精度，**必须用带真值的测试集做批量对照**（这正是对照实验的意义）。

### 这个案例说明了什么（重要）

| 认识 | 说明 |
|---|---|
| **细粒度识别极度依赖局部细节** | 车标只有几十像素宽，误读一个字就全盘皆错 |
| **幻觉的特征是"有推理、有细节、但前提错"** | 它顺着错误线索编出了一整套"依据" |
| **"把握度高"与正确性无关** | 它错的时候同样自信 |
| **专用模型的"弱"被低估了** | 本地模型仅 25.87 MB，在这个类上 **8/8 全对** |
| **这正是"必须用真值评估"的理由** | 没有真值，你会以为云端对、本地错 |

### 附：本地模型在类别 0004 上的验证

| 图片 | 本地模型 Top-1 |
|---|---|
| 0004_0001 ~ 0004_0008（共 8 张） | **全部 = 曹操汽车_曹操60** |
| Top-1 命中 / Top-5 命中 / 大类正确 | **8/8 / 8/8 / 8/8** |

## 五、为什么还要自己做模型（对比结论）

| 维度 | **云端多模态 LLM** | **我们的 Car-1000 模型** |
|---|---|---|
| 识别精度（实测样本） | **4/4 全对** | 1000 类，86.77% |
| 输出形式 | 自然语言描述 | 固定类别 + 概率 |
| 模型规模 | 数百亿参数以上 | **2,556 万** |
| 运行时内存 | 上百 GB（云端） | **约 128 MB** |
| 硬件 | GPU 集群 | **KPU，无 GPU** |
| **能否装在 K230D** | ❌ **不能** | ✅ **能，28 FPS** |
| 联网 | **必须** | ❌ **不需要** |
| 单次成本 | 有 token 费用 | **0** |
| 响应速度 | 秒级 | **28 FPS** |

> **结论：两者是分工，不是替代。**
> 云端 LLM 强在**理解与表达**；端侧小模型强在**离线、实时、低成本**。

---

## 六、结论摘要

> 本节实测了云端多模态大模型的车辆识别能力。**给纯色图测试，4/4 全对；给真实的 Car-1000 图片，能准确说出品牌和车系，甚至给出了宝马 M5 的底盘代号 F10。**
>
> **它的能力是真实的。** 但它有两个硬约束：**必须联网**，而且**需要云端 GPU**。
>
> 同一个任务换一条路：训练一个 25 MB 的专用模型，量化后放到 **¥300、128 MB 内存、没有 GPU** 的开发板上，**离线跑到 28 FPS**。
>
> **这条路线精度略低，但它能去大模型去不了的地方。**

### 一个方法教训

> 最初测出"大模型读不了图"，实际原因是 **`max_tokens` 设置过小**——思考链耗尽了预算，正文还没输出就被截断，返回了空字符串。
>
> 这件事说明：**"实测"本身也可能因为方法不当而给出错误结论。** 看到异常结果时，先检查自己的实验设置，再下判断。
