# 脚本总账

> 本仓库共 **25 个主流程脚本**，分布在三个代码目录中。
> 本文档说明每个脚本的用途与运行方式。

---

## 零、根目录入口文件（环境配置与启动）

这些文件不在代码子目录里，但**复现时必须先用到**。

| 文件 | 类型 | 作用 |
|---|---|---|
| `requirements.txt` | 依赖清单 | 主环境依赖（训练 / 推理 / 网页 Agent） |
| `requirements-k230.txt` | 依赖清单 | K230 转换环境依赖（nncase，**必须 Python 3.10–3.12**） |
| `install.bat` | 一键脚本 | 装主环境：找 Python → 检测显卡 → 装 CUDA 版 PyTorch → 按清单装依赖 → 自检 |
| `install-k230.bat` | 一键脚本 | 装转换环境：检查 Python 版本 → 在 ASCII 路径建 venv → 装 nncase → 验证 KPU 插件 |
| `check_env.py` | 脚本 | 环境自检：逐项检查依赖版本、显存；`--k230` 检查转换环境 |
| `04_代码_网页Agent/start.bat` | 一键脚本 | 启动网页 Agent，自动补齐 Agent 专属依赖 |

> ⚠️ 三个 `.bat` 都必须是**纯 ASCII + CRLF 换行**，否则中文 Windows
> （代码页 936）下 cmd 会解析异常（表现为每行首字符被吃掉）。

## 一、主流程脚本（25 个）

这些脚本按顺序执行，即可完成整个项目。

### 1.1 模型训练（`02_代码_模型训练/`，12 个脚本）

#### Car-1000 主线（推荐，中国车型）

| 脚本 | 功能 | 用法 |
|---|---|---|
| `prepare_car1000.py` | **数据准备**：把原始编号目录整理成 ImageFolder 结构（train/val/test） | `python prepare_car1000.py --src <原始目录> --dst <输出目录>` |
| `bench_car1000.py` | **训练前计时与显存实测**：测出每轮真实耗时，决定总轮数与可行性 | `python bench_car1000.py --data <数据目录>` |
| `train_car1000.py` | **正式训练**：1000 类，ResNet-50 迁移学习 | `python train_car1000.py --data <数据目录>` |
| `evaluate_car1000.py` | **分层评估与混淆分析**：Top-1/Top-5/大类准确率 + 误认归因 | `python evaluate_car1000.py --ckpt <权重> --data <数据目录>` |
| `predict_car1000.py` | **推理工具**：单张或批量识别 | `python predict_car1000.py --img 车.jpg` |
| `export_onnx_car1000.py` | **导出 ONNX** + 与 PyTorch 对拍验证 | `python export_onnx_car1000.py --ckpt <权重>` |

#### Stanford Cars 基线（第一阶段对照）

| 脚本 | 功能 |
|---|---|
| `prepare_cars.py` | 数据准备（Stanford Cars 版） |
| `train_cars.py` | 训练 196 类基线模型 |
| `analyze_confusion.py` | 混淆结构分析（把「哪些车认错」提升为「为什么认错」） |
| `export_onnx.py` | 导出 Stanford 版 ONNX |
| `predict_cars.py` | 推理工具（Stanford 版） |
| `deploy_check.py` | **量化精度实测**：对比不同骨干网络的 INT8 量化损失 |

> 💡 **为什么保留 Stanford 版？** 因为它是「数据集选择」这个核心论点的证据。
> 没有它，就无法说明「为什么必须换数据集」。

### 1.2 K230 部署（`03_代码_K230部署/`，9 个脚本）

| 脚本 | 运行环境 | 功能 |
|---|---|---|
| `convert_to_kmodel_car1000.py` | **独立 Python 3.10–3.12** | **ONNX → kmodel**（nncase 量化编译），部署核心步骤 |
| `verify_kpu_plugin.py` | 同上 | 验证 nncase 的 k230 插件是否安装成功 |
| `verify_mean_scale_bug.py` | 训练环境 | 复现并验证「归一化量纲」bug（本项目最隐蔽的问题） |
| `check_micropython_compat.py` | 任意 | **板端脚本静态检查**：找出 MicroPython 不支持的写法 |
| `k230_main.py` | **板端**（CanMV IDE） | **主程序**：摄像头采集 → 推理 → OSD 显示，28 FPS |
| `k230_board_test.py` | **板端** | 60 秒离线稳定性测试，结果写到 TF 卡 |
| `read_board_libs.py` | **板端** | 读取板卡固件与库版本（排查环境问题用） |
| `convert_to_kmodel.py` | 独立环境 | Stanford 版转换脚本（对照） |
| `verify_deploy.py` | 训练环境 | 上板前最后一道关卡：确认 ONNX 与 PyTorch 精度一致 |

> ⚠️ **`check_micropython_compat.py` 很重要**：MicroPython 是 CPython 的精简子集，
> 很多常用函数不存在（如 `os.path.exists`）。上板前先跑这个检查，
> 能避免反复「改代码 → 拷进 TF 卡 → 上板 → 发现报错」的循环。

### 1.3 网页 Agent（`04_代码_网页Agent/`，4 个脚本 + 4 个配置文件）

| 文件 | 功能 |
|---|---|
| `start.bat` | **一键启动**：自动检查依赖 → 启动服务 → 打开浏览器 |
| `server.py` | 网页服务（Python 标准库，无需 Flask），含 SSE 流式推送 |
| `agent_core.py` | **ReAct 核心循环**：思考 → 行动 → 观察 → 再思考 |
| `tools.py` | 三个工具：本地模型识别 / 云端多模态识别 / 联网搜索 |
| `config_loader.py` | 配置加载（环境变量 > config.ini > 默认值） |
| `config.example.ini` | 配置模板（复制为 `config.ini` 后填入自己的密钥） |
| `static/index.html` | 网页界面（上传图片 + 实时显示思考过程） |
| `README.md` | Agent 使用说明 |
