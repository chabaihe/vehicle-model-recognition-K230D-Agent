# 车辆识别 Agent

> 一个把 **ReAct 架构**、**本地深度学习模型**、**云端多模态大模型**、**联网搜索** 串起来的车辆识别助手。
> 双击 `start.bat` 即可运行，浏览器自动打开。

---

## 一、快速开始

```
双击  start.bat
```

浏览器会自动打开 `http://127.0.0.1:8000`，上传车辆图片即可。

> 首次运行会自动检查并安装缺的依赖（onnxruntime / openai / tavily-python）。
> 完整的依赖清单见仓库根目录的 `requirements.txt`。

### 手动启动

```powershell
cd "<本目录>"
python server.py
```

### 依赖

| 包 | 用途 |
|---|---|
| `onnxruntime` | 本地模型推理（离线，约 17 ms） |
| `openai` | 调用 DeepSeek 云端多模态识别 |
| `tavily-python` | 联网检索车型参数价格（`import tavily`） |
| `pillow` / `numpy` | 图片预处理 |

> 网页服务本身只用 Python 标准库 `http.server`，**不需要 Flask**。

---

## 二、它在做什么

采用经典 **ReAct**（Reasoning + Acting）模式：

```
用户上传车辆图片
      ↓
  LLM 思考（Thought）
      ↓
  选择工具（Action）──┬─→ classify_local()   本地模型识别（离线 17ms）
                      ├─→ analyze_vision()   云端多模态识别（联网 5s）
                      └─→ search_specs()     联网查参数价格
      ↓
  拿到结果（Observation）→ 塞回对话历史
      ↓
  循环，直到 Finish[最终答案]
```

**网页上能实时看到每一步**（SSE 流式推送）。

---

## 三、三个工具

| 工具 | 依赖 | 耗时 | 说明 |
|---|---|---|---|
| `classify_local()` | **离线** | **约 17 ms** | 本地 Car-1000 模型，1000 类，25.87 MB ONNX |
| `analyze_vision()` | 需联网 | 约 5 s | 云端多模态大模型，能给出自然语言依据 |
| `search_specs(query)` | 需联网 | 约 5 s | Tavily 搜索车辆参数/价格 |

> **设计要点**：图片**不进 LLM 对话上下文**，由工具持有，工具返回**纯文本**给 LLM。
> 好处：多轮循环时不重复传输图片，省 token、避免格式问题。

## 四、实测效果（黄色宝马 M5 照片）

Agent 自动跑了 4 轮，**21 秒**得出结论：

| 轮次 | 动作 | 结果 |
|---|---|---|
| 1 | `classify_local()` | 宝马_宝马M5 [轿车] 置信度 **8.37%**，Top5 全是宝马 |
| 2 | `analyze_vision()` | 宝马 M5（**F90 代**），把握度高，并给出识别依据 |
| 3 | `search_specs()` | ￥1,468,900 起，V8 双涡轮 + 电机，727 马力 |
| 4 | `Finish[...]` | 综合两条路线的对比结论 |

**Agent 自己总结出的对比**：

> - **本地离线模型**：Top1 命中「宝马_M5」，但置信度仅 8.37%，只能确定是宝马轿车；**优点：离线、零成本、大类判断可靠**。
> - **云端多模态大模型**：准确给出 M5（F90），并说明依据（M5 尾标、四出排气、L 型尾灯、专属黄漆）；**语义理解明显更强，但需联网、有延迟与成本**。

## 七、已知限制

| 限制 | 说明 |
|---|---|
| 首次调用本地模型慢 | 约 0.4 s 加载模型，之后走缓存（纯推理 17 ms） |
| 依赖网络的两个工具 | 断网时只有 `classify_local()` 可用（这本身也是个对照点） |
| 大模型输出措辞可能变化 | 同一张图多次识别，描述用词可能不同，但结论稳定 |
| **必须给足 `max_tokens`** | 云端模型带思考链，预算不足会导致正文被截断（返回空） |
| 不做目标检测 | 输出的是类别，不是"框住车辆"。画框需要另加检测模型 |

## 八、这个 Demo 想说明什么

它把**两条技术路线**放在同一个界面里对照：

| | **本地小模型** | **云端大模型** |
|---|---|---|
| 精度 | 1000 类，86.77% | 通用理解更强 |
| 规模 | **25.87 MB** | 数百亿参数以上 |
| 能否离线 | ✅ **能** | ❌ 不能 |
| 速度 | **17 ms** | 约 5 s（含网络） |
| 成本 | **0** | 有 token 费用 |
| 能装进 K230D 吗 | ✅ **能（28 FPS）** | ❌ **装不下** |

> **技术没有优劣之分，只有合适之分。**
> 云端大模型负责"理解与表达"，端侧小模型负责"离线实时判别"。
