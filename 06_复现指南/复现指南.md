## 第 0 步：先弄清楚这个项目要做什么

### 这个项目解决的问题

输入一张汽车照片，输出这辆车的**具体型号**（比如「宝马_宝马M5」）。

难点在于：**车型之间的差别非常细微**。
比如「领克 01」和「领克 01 PHEV」外观几乎一样，只是前者是燃油车、后者是插混车。
这种任务叫**细粒度分类**。

### 整体流程

```
①  准备数据集
       ↓
②  训练模型（ResNet-50，1000 个类别）
       ↓
③  评估模型（准确率多少？错在哪儿？）
       ↓
④  把模型压缩 + 转换格式（97 MB → 25.87 MB）
       ↓
⑤  部署到开发板（离线实时识别，28 FPS）
```

![图 5 技术路线全景](../01_技术路线图/arch_overview.png)

### 你需要准备什么

| 项目 | 要求 | 说明 |
|---|---|---|
| **电脑** | Windows，有 NVIDIA 显卡 | 显卡显存 **至少 4 GB**，本项目使用 RTX 4060 Laptop 8 GB |
| **开发板** | 正点原子 K230D BOX（可选） | 约 300 元。**做第 7 步才需要** |
| **TF 卡 + 读卡器** | ≥ 8 GB | 给开发板用 |
| **时间** | 约 1 天（不含开发板） | 训练模型约 1.5 小时 |

> 💡 **没有显卡怎么办？**
> 可以用 Google Colab 的免费 GPU 训练；
> 或者**完全跳过训练**，直接用仓库自带的 INT8 模型跑网页 Agent（第 8 步），
> 几分钟就能看到识别效果，全程不需要显卡。

> 📌 **只想先看看效果？** 最短路径是：
> 第 1 步装环境 → 第 8 步跑 Agent。仓库已自带模型，不需要训练。

## 第 1 步：装好环境

### 1.1 装 Python

**为什么**：Python 是运行所有脚本的语言。

1. 打开 https://www.python.org/downloads/
2. 下载 **Python 3.12**（不要下最新的 3.13/3.14，某些库还不支持）
3. 安装时**务必勾选 `Add python.exe to PATH`**（在第一屏底部）

**验证**：按 `Win + R`，输入 `cmd` 回车，然后输入：

```cmd
python --version
```

看到 `Python 3.12.x` 就成功了。

> ⚠️ 如果提示"不是内部或外部命令"，说明第 3 步没勾选，需要重新安装。

### 1.2 安装需要的库

**为什么**：PyTorch 等库不是 Python 自带的，需要单独装。

本项目把依赖写在根目录的 **`requirements.txt`** 里，不需要一条条手敲。

#### 方式 A：一键安装（推荐，新手用这个）

**双击仓库根目录的 `install.bat`** 即可。它会自动完成：

1. 找到 Python 并检查版本
2. 检测有没有 NVIDIA 显卡 → 有就装 CUDA 版 PyTorch，没有才装 CPU 版
3. 按 `requirements.txt` 装其余依赖
4. 最后调用 `check_env.py` 逐项验证并打印结果

看到 `DONE. Main environment is ready.` 就说明装好了。

#### 方式 B：手动安装

```cmd
:: ① 先装 GPU 版 PyTorch（这一步最慢，约 5-10 分钟）
```

> `torch.cuda.is_available()` 会返回 `False`，训练慢几十倍。
>
> CUDA 12.1 驱动的机器请把 `cu126` 换成 `cu121`。

## 第 2 步：准备数据集

### 2.1 为什么要换数据集

项目一开始使用的是 **Stanford Cars** 数据集，
它包含 196 类、16,185 张图片，是很经典的基准。

但检查后发现**两个硬伤**：

| 问题 | 具体数据 |
|---|---|
| 年份太旧 | 覆盖 1991–2012 年，**2013 年以后 0 类** |
| 没有中国车 | 全库检索比亚迪、蔚来、小鹏、理想、吉利、长安、五菱、小米，**命中 0 个** |

**结论**：这个模型认不出中国路上的车。

因此改用 **Car-1000** 数据集。

### 2.2 获取 Car-1000 数据集

| 项目 | 内容 |
|---|---|
| 规模 | 1,000 类车型 / 166 个品牌 / 140,267 张图片 |
| 年份覆盖 | 1960 年代 – 2020 年代 |
| 标签 | 中文「品牌_车型」格式 |
| 数据来源 | 中国汽车媒体「懂车帝」 |
| 发布信息 | 2025 年由北京航空航天大学、上海人工智能实验室、东南大学等合作发布 |

> ⚠️ **数据集不包含在本仓库中**（14 万张图体积过大）。
> 请通过数据集发布方提供的渠道获取，并遵守其许可协议，仅用于学习研究。

### 2.3 整理成训练所需的结构

**为什么**：原始数据集是按编号目录存放的，而 PyTorch 需要一个固定的目录结构。

**原始结构**（假设）：

```
Car-1000-dataset/
├── all_images/
│   ├── 0000/  (这个类的所有图片)
│   ├── 0001/
│   └── ...
├── train.json    (记录哪些图片属于训练集)
├── val.json
└── test.json
```

**目标结构**（ImageFolder 格式）：

```
Car1000_split/
├── train/
│   ├── 江铃_凯运/
│   ├── 远程汽车_远程星智H/
│   └── ...
├── val/
└── test/
```

**执行整理脚本**：

```cmd
cd /d D:\vehicle-recognition\02_代码_模型训练
python prepare_car1000.py --root "D:\data\Car-1000-dataset" --out "D:\data\Car1000_split"
```

**验证**：进入 `D:\data\Car1000_split\train`，应该看到 1000 个以车型命名的文件夹。

> 💡 该脚本使用**硬链接**而非复制，所以不会额外占用磁盘空间（同一分区时）。

### 2.4 检查数据划分

整理完成后，脚本会输出数据统计。期望结果：

| 划分 | 图片数 | 占比 |
|---|---:|---:|
| 训练集 | 83,756 | 59.7% |
| 验证集 | 27,658 | 19.7% |
| 测试集 | 28,853 | 20.6% |

## 第 3 步：实测训练成本

### 为什么先做这一步

Car-1000 有 8.3 万张训练图。**如果不先测一下每轮要多久，可能跑到一半发现要 20 小时。**

这一步会实测：每个 epoch 的真实耗时、显存占用峰值，帮你决定训练总轮数。

**执行**：

```cmd
python bench_car1000.py --data "D:\data\Car1000_split"
```

**实测结果**（RTX 4060 Laptop 8 GB）：

| 指标 | 数值 |
|---|---:|
| 每轮耗时 | 约 6.5 分钟 |
| 峰值显存 | 3.05 GB |
| 建议总轮数 | 15 轮（约 97 分钟） |

> 💡 如果显存不足报错，把脚本里的 `--batch-size` 从 64 调小到 32 或 16。

## 第 4 步：训练模型

### 执行训练

```cmd
python train_car1000.py --data "D:\data\Car1000_split" --epochs 15 --batch 64
```

**训练过程中你会看到**：

```
Epoch 1/15  train_loss=4.821  train_acc=12.3%  val_top1=31.2%  val_top5=58.7%
Epoch 2/15  train_loss=3.412  train_acc=34.8%  val_top1=52.1%  val_top5=76.4%
...
Epoch 15/15 train_loss=0.412  train_acc=94.2%  val_top1=86.9%  val_top5=98.2%
```

### 关键配置说明（不用改，了解即可）

| 配置 | 取值 | 为什么这么选 |
|---|---|---|
| 骨干网络 | ResNet-50 | 见下方说明 |
| 输入尺寸 | 224×224 | 标准尺寸，兼顾速度与精度 |
| 优化器 | AdamW，学习率 3e-4 | 迁移学习的常用选择 |
| 学习率调度 | 余弦退火 | 后期自动降低学习率，收敛更稳 |
| 损失函数 | 交叉熵 + **类别加权** + 标签平滑 0.1 | 应对类别不均衡（最多的类 200+ 张，最少的仅 2 张） |

> 💡 **为什么用 ResNet-50 而不是更小的 MobileNetV3？**
> 实测结果：MobileNetV3 浮点精度 83.52%，但 **INT8 量化后暴跌到 66.19%**
>（掉了 17.33 个百分点）；而 ResNet-50 量化只掉 0.87 个百分点。
> 因为端侧部署必须量化，所以**更大的 ResNet-50 反而更划算**。

### 训练完成

权重会保存到 `results/best_resnet50.pth`（约 97 MB）。

**验证**：训练日志最后几行的 `val_top1` 应该在 **86% 以上**。

## 第 5 步：评估模型

### 执行评估

```cmd
python evaluate_car1000.py --ckpt results/best_resnet50.pth --split test
```

### 会得到什么

脚本会输出三个层次的指标：

| 指标 | 实测结果 |
|---|---:|
| Top-1 准确率（具体车型） | **86.77%** |
| Top-5 准确率 | 98.16% |
| **车辆大类准确率** | **98.24%** |

还会生成混淆矩阵，并分析"哪些车型容易互相认错"。

### 怎么理解这两个数字的差距

细粒度 86.77% 与 大类 98.24% 相差 **11.5 个百分点**，
这说明：**模型几乎不会把 SUV 认成轿车**，
它的错误全部集中在同一大类内部 —— 知道这是轿车，但没分清是哪款。

进一步统计发现：**最严重的 100 组误认，100% 发生在同品牌内部，跨品牌误认为 0 次**。

主要失败模式是**同款车的不同动力形式**：

| 真实车型 | 被认成 | 差别 |
|---|---|---|
| 领克 01 | 领克 01 PHEV | 燃油 vs 插混 |
| 沃尔沃 XC90 | XC90 RECHARGE | 燃油 vs 插混 |
| 丰田 bZ4X（广汽） | bZ4X（一汽） | 生产厂商不同 |

> 这些车型外观几乎一致，仅在前翼子板处多一个充电口盖板，
> 在 224×224 分辨率下不足十个像素。

## 第 6 步：在电脑上跑识别

> ⚠️ **前置条件：本步需要 `results/best_resnet50.pth`（第 4 步训练产物）。**
>
> 这个 97.80 MB 的权重文件**没有随仓库分发**（GitHub 单文件上限 100 MB，
> 且 `.pth` 可由训练完全重现）。所以：
>
> | 你的情况 | 该怎么做 |
> |---|---|
> | 已经完成第 4 步训练 | 往下走本步即可 |
> | **还没训练，只想看识别效果** | **直接跳到[第 8 步](#第-8-步跑网页-agent可选)** —— 网页 Agent 用仓库自带的 INT8 模型（24.53 MB），开箱即用，不需要 `.pth` |
>
> 想在不训练的情况下用命令行识别，可先用 Agent 的本地识别接口（见第 8 步），
> 或自己训练一次（约 97 分钟）后再回到本步。

### 先导出 ONNX 格式

**为什么**：`.pth` 只能在 PyTorch 里跑，导出成 ONNX 才能被其它工具读取。

```cmd
python export_onnx_car1000.py --ckpt results/best_resnet50.pth
```

脚本会做两件事：
1. 导出 `cars1000_resnet50_224.onnx`（97.41 MB）
2. **对拍验证**：用同一批图片分别跑 PyTorch 和 ONNX，逐张比对结果

**验证**：脚本最后应输出 `一致率: 100.00%`。
如果不是 100%，说明导出或预处理有问题，**先别往下做**。

### 单张图片识别

```cmd
python predict_car1000.py --img "D:\photos\my_car.jpg"
```

输出示例：

```
本地模型识别结果（Car-1000，1000 类；离线推理 16 ms，不联网）：
  Top1: 曹操汽车_曹操60 [轿车]  置信度 99.41%
  Top2: 睿蓝汽车_睿蓝7 [SUV]    置信度 0.02%
  Top3: 奇瑞_艾瑞泽5 GT [轿车]  置信度 0.02%
  → 判断车辆大类：轿车（该模型大类准确率 98.24%）
```

> ⚠️ **关于置信度**：它不是校准过的概率，**不能直接用来判断对错**。
> 实测表明，模型认对时置信度可能只有 10%，也可能高达 99%；
> 而在一次板端配置出错时，置信度恒定 100% 但结果全错。
> 更可靠的做法是看**结果是否稳定**：连续多张图结果不乱跳，一般就是对的。

## 第 7 步：部署到 K230D 开发板

> ⭐⭐⭐⭐ **这是全项目最难的一步**。请先读完本节的"三个前置提醒"再动手。

### 三个前置提醒

| # | 提醒 | 说明 |
|:---:|---|---|
| 1 | **必须用独立的 Python 环境** | 训练环境（3.12/3.14）装不上 nncase。装一个 Python 3.12 的独立虚拟环境 |
| 2 | **上板前先做静态检查** | 跑 `check_micropython_compat.py`，避免反复插拔 TF 卡 |
| 3 | **板卡启动方式很关键** | K230D 默认从板载存储启动，**必须按住 KEY2 再复位**才能从 TF 卡启动 |

### 7.1 创建独立的转换环境

**方式 A：一键安装（推荐）**

双击仓库根目录的 **`install-k230.bat`**。它会自动：检查 Python 版本是否为 3.10–3.12 → 在 ASCII 路径建虚拟环境 → 按 `requirements-k230.txt` 安装 → 验证 KPU 插件。

如果你机器上的 Python 3.12 不在默认位置，把路径传进去：

```cmd
install-k230.bat D:\Python312\python.exe
```

**方式 B：手动安装**

```cmd
:: 创建虚拟环境（路径必须是纯英文，原因见下方警告）
python -m venv C:\vr_nncase_env

:: 激活
C:\vr_nncase_env\Scripts\activate

:: 按清单安装（nncase 官方 wheel 只支持 cp39–cp313）
pip install -r requirements-k230.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**验证**：

```cmd
python check_env.py --k230
```

应看到 `k230 Compiler 创建成功（KPU 插件已生效）`。

> ⚠️ **这里有三个常见问题**（第 3 个最隐蔽）：
>
> **坑 1：`nncase` 和 `nncase-kpu` 是两个不同的包，两个都要装。**
> 只装前者会报 `KeyNotFoundException: 'k230' was not present in the dictionary`，
> 因为编译器本体和 KPU 硬件插件是分开发布的。
>
> **坑 2：`nncase-kpu` 在 PyPI 上没有 Windows 版。**
> PyPI 只发布了 Linux wheel（`manylinux2014_x86_64`），所以在 Windows 上执行
> `pip install nncase-kpu==2.11.0` 会报
> `Could not find a version that satisfies the requirement ... (from versions: none)`。
> Windows 的 `nncase_kpu-2.11.0-py2.py3-none-win_amd64.whl`（1.27 MB）只在
> **GitHub Releases** 里。`requirements-k230.txt` 已经用直链解决了这个问题：
>
> ```
> nncase-kpu @ https://github.com/kendryte/nncase/releases/download/v2.11.0/nncase_kpu-2.11.0-py2.py3-none-win_amd64.whl ; sys_platform == "win32"
> ```
>
> **坑 3：虚拟环境不能放在含中文的路径下。**
> nncase 是 .NET 库，它的 `hostfxr` 加载器**无法处理非 ASCII 路径**。
> 如果虚拟环境（或项目本身）位于中文目录，`import nncase` 会直接失败：
>
> ```
> RuntimeError: Failed to initialize hostfxr: 0x80008094.
> ```
>
> 所以 `install-k230.bat` 默认把环境建在
> `%LOCALAPPDATA%\vr_nncase_env`（通常是纯英文路径），并会自动检测路径是否含中文、
> 含则回退到 `C:\vr_nncase_env`。

### 7.2 转换模型

```cmd
python convert_to_kmodel_car1000.py --onnx ..\05_模型文件\cars1000_resnet50_224.onnx
```

会得到 `cars1000_resnet50_224.kmodel`（**25.87 MB**）。
本仓库的 `05_模型文件/` 里已包含这个文件，可以直接用。

**转换时做了什么**：
1. 图优化
2. **INT8 量化**（32 位浮点 → 8 位整数，体积压到 1/4）
3. 指定预处理参数（**这里的量纲必须配对，否则结果全错**）

### 7.3 拷贝到 TF 卡

把以下文件拷到 **TF 卡的 `/sdcard/` 目录**（不是 BIN 分区）：

| 文件 | 说明 |
|---|---|
| `k230_main.py` | 重命名为 `main.py`，板卡上电自动运行 |
| `cars1000_resnet50_224.kmodel` | 模型 |
| `class_names_cn.txt` | 类别名称表 |

> ⚠️ **不要动** TF 卡自带的 `examples/`、`libs/`、`res/` 等目录。

### 7.4 上板运行

1. 把 TF 卡插入 K230D BOX
2. **按住开发板上的 KEY2 按键不放**
3. 按一下 **复位键**
4. 松开 KEY2

> ⚠️ **这一步是关键**。如果不按 KEY2，板卡会从板载存储启动，
> 进入一个图形桌面，CanMV IDE 连不上，串口也没有输出。

5. 打开 CanMV IDE，连接串口
6. 运行 `main.py`

**验证**：LCD 上应显示摄像头画面，车辆上有一个框，
框上方显示车型名称与置信度。**绿色框**表示置信度 ≥ 50%，**橙色框**表示不确定。

期望帧率：**28 FPS**。

### 7.5 如果结果全错怎么办

**症状**：电脑上识别正确，板子上识别完全错误，且**置信度恒定为 100%**。

**这是本项目最隐蔽的 bug**，原因是**归一化参数的量纲配置错误**。
排查思路（当时采用的四步）：

1. 在电脑端用同一张图分别跑 PyTorch 与 ONNXRuntime，确认模型本身没问题
2. 在电脑上**人为构造各种预处理错误**（不归一化、只标准化、通道顺序错），逐一模拟
3. 发现只有"**缺少归一化**"这一种情况会让置信度饱和到 100%
4. 回到转换脚本，检查归一化参数的量纲是否与 `input_range` 配对

**核心要点**：`input_range` 与 `mean`/`std` **必须用同一个数值尺度**。
比如 `mean=[0.485, 0.456, 0.406]`（0–1 尺度）时，
`input_range` 必须是 `[0, 1]`，**不能写 `[0, 255]`**。

> 📖 详细排查过程见 [`../08_技术文档/01_问题与发现汇总.md`](../08_技术文档/01_问题与发现汇总.md)

## 第 8 步：跑网页 Agent（可选）

### 这是什么

一个网页工具：上传车辆图片，它会同时用**本地模型**和**云端大模型**识别一遍，
再联网搜索该车参数，最后给出综合结论。

![图 6 车辆识别智能体的 ReAct 工作流程](../01_技术路线图/fig6_agent_flow.png)

> ✅ **本地模型已随仓库附带，不需要下载也不需要训练。**
>
> 文件：`05_模型文件/cars1000_resnet50_224_int8.onnx`（24.53 MB，INT8 动态量化版）
> 代码会自动按「浮点版 → INT8 版」的优先级查找，找到就能用。
>
> 这是**便于分发的轻量版**，实测精度比浮点版低约 2.6 个百分点（用于演示足够）。
> 若要最高精度，把 `cars1000_resnet50_224.onnx`（第 6 步导出）放进
> `05_模型文件/` 即可自动优先使用，**不需要改任何代码**。

### 8.1 配置密钥

进入 `04_代码_网页Agent/`，把 `config.example.ini` 复制一份改名为 `config.ini`，
填入密钥：

```ini
[api]
deepseek_key = 你的_deepseek_密钥
tavily_key   = 你的_tavily_密钥
```

| 密钥 | 用在哪 | 获取地址 |
|---|---|---|
| DeepSeek | 云端多模态识别 | https://platform.deepseek.com |
| Tavily | 联网搜索车辆参数 | https://tavily.com |

> ⚠️ `config.ini` 已在 `.gitignore` 中，**不会**被提交到 Git。
> 千万不要把密钥硬编码进代码或者发到网上。

### 8.2 启动

**双击 `start.bat`** 即可。脚本会自动检查依赖、安装缺失的库、启动服务并打开浏览器。

**验证**：浏览器自动打开 `http://127.0.0.1:8000`，页面上有三个状态徽章
（本地模型 / 云端大模型 / 联网搜索），均应显示为 ✓。

### 8.3 会看到什么

上传图片后，页面会**实时显示 Agent 的每一步思考**：

```
第 1 轮  THOUGHT  先看看本地模型怎么说
         ACTION   classify_local()
         OBSERVATION  曹操汽车_曹操60 [轿车] 置信度 33.32%

第 2 轮  THOUGHT  置信度不高，用云端大模型再确认一次
         ACTION   analyze_vision()
         OBSERVATION  哈弗枭龙MAX [SUV]，把握度高

第 3 轮  THOUGHT  两者不一致，搜索一下这车的参数
         ACTION   search_specs("哈弗枭龙MAX 参数 价格")
         ...
```

### 8.4 借此发现的问题

这个工具最有价值的地方，是它**暴露了云端大模型的一个真实问题**：

| 识别方法 | 结果 | 是否正确 |
|---|---|---|
| 本地模型（25.87 MB，离线） | **曹操汽车_曹操60（轿车）** | ✅ **正确** |
| 云端大模型（联网） | 哈弗枭龙MAX（SUV） | ❌ **错误** |

云端模型把车头的 **MAPLE（枫叶汽车）** 标志**误读成了 HAVAL（哈弗）**，
然后顺着这个错误线索，编出了一整套"识别依据"——
封闭式前脸、7 字形 LED 大灯、新能源绿牌，说得头头是道，**但前提就是错的**。

**这就是 AI 幻觉**：它不是在胡说，而是顺着一个错误线索，
认真推理出了一个错误结论。而且它自报"把握度高"。

**对照验证**：将这一类的 8 张测试图全部用本地模型跑了一遍，**8 张全部正确**。

> 📖 完整记录见 [`../08_技术文档/14_云端大模型能力实测.md`](../08_技术文档/14_云端大模型能力实测.md)

## 常见问题

### Q1：显存不够报错 `CUDA out of memory`

把 `--batch-size` 从 64 改成 32 或 16。
如果还不行，把输入尺寸从 224 改成 192（会损失一些精度）。

### Q2：`nncase` 装不上

按顺序排查：

| 报错 | 原因 | 解决 |
|---|---|---|
| `No matching distribution found for nncase` | Python 版本超出 3.10–3.12 | 另装 Python 3.12，用 `install-k230.bat D:\Python312\python.exe` |
| `Could not find a version that satisfies the requirement nncase-kpu ... (from versions: none)` | **PyPI 上没有 Windows 版 `nncase-kpu`**，只有 Linux wheel | 用 `requirements-k230.txt`（已配 GitHub 直链），或手动下 `nncase_kpu-2.11.0-py2.py3-none-win_amd64.whl` |
| `KeyNotFoundException: 'k230' was not present in the dictionary` | 只装了 `nncase`，漏了 `nncase-kpu` 插件 | 补装 `nncase-kpu==2.11.0` |
| **`RuntimeError: Failed to initialize hostfxr: 0x80008094`** | **虚拟环境在含中文的路径下** | nncase 是 .NET 库，路径必须纯英文。把环境建到 `C:\vr_nncase_env` |

> 💡 最后一条最隐蔽：`nncase` 能 import、版本也对，但一初始化就崩。
> 它和"模型量化不能放中文路径"是同一类问题 —— .NET / 原生组件对非 ASCII 路径兼容性差。

### Q3：板卡连不上 CanMV IDE

99% 是启动方式问题。**必须按住 KEY2 再按复位**，让板卡从 TF 卡启动。
如果还是不行，检查 TF 卡是否插紧、`main.py` 是否在 `/sdcard/` 根目录。

### Q4：结果全错、置信度 100%

归一化参数量纲配置错误。见 [第 7.5 节](#75-如果结果全错怎么办)。

### Q5：识别率比预期低

检查三点：
1. **拍摄角度** —— 训练图以正面和侧前方 45° 为主，正侧面识别率会下降
2. **类别是否在 1000 类中** —— 数据集之外的车型识别不了
3. **图片是否清晰** —— 车标模糊会影响判断

### Q6：为什么我的准确率比 86.77% 低？

几个可能原因：
- 没加载 ImageNet 预训练权重
- 数据划分没按官方的来（自己随机切分会导致结果不可比）
- 训练轮数不够
- 类别映射顺序错了（这是很隐蔽的坑，会导致推理正常但标签整体错位）
